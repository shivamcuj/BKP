Overview

Detailed Notes
  • Data Structure is the representation of logical relationships between individual data elements
  • It's a way of organizing data items considering both the elements stored and their relationships
    • Fundamental concept in computer science for efficient data organization
    • Affects both structural and functional aspects of program design
  • The core equation: Program = Algorithm + Data Structure
    • Algorithm: Step-by-step procedure to solve a particular function
    • Data Structure: Organization of data with logical relationships retained
    • To develop a program, select appropriate data structures for the algorithm
  • Data structures and algorithms together form a complete program
Short Notes

Data Structure: Organization of data considering elements + relationships.

Core Equation: Program = Algorithm + Data Structure

Algorithm: Step-by-step procedure; Data Structure: Organized data with logical relationships.

Choice of data structure directly impacts program efficiency and design.

Classification of Data Structures

Detailed Notes
  • Data structures are divided into two broad categories:
    • Primitive Data Structures: Basic structures directly operated by machine instructions
    • Non-Primitive Data Structures: Sophisticated structures derived from primitive ones
  • Primitive Data Structures:
    • Integer, Float, Character, Pointer
    • Different representations on different computers
    • Directly supported by programming languages
  • Non-Primitive Data Structures:
    • Emphasize structuring groups of homogeneous or heterogeneous data
    • Linear Lists: Array, Linked List, Stack, Queue
    • Non-Linear Lists: Trees, Graphs
  • Key difference: Primitive structures are built into languages; non-primitive are built from primitive structures linked meaningfully
Short Notes

Two Main Categories: Primitive and Non-Primitive

Primitive: Basic (int, float, char, pointer) - directly operated by machine

Non-Primitive: Derived from primitive (Linear: Array, LL, Stack, Queue; Non-linear: Trees, Graphs)

Key Distinction: Primitive = built-in; Non-primitive = constructed from primitive

Primitive Data Structures

Detailed Notes
  • Basic structures directly operated upon by machine instructions
  • Different representations may exist on different computer architectures
  • Types of primitive data structures:
    • Integer: Whole numbers without fractional components
    • Float/Floating-point: Numbers with decimal points or exponential notation
    • Character: Single alphabets, digits, or symbols
    • Pointer: Memory address variables pointing to other data
    • String constants (though sometimes considered derived)
  • Characteristics:
    • Built directly into programming languages
    • Have fixed size in memory (architecture-dependent)
    • Operations on them are typically atomic at hardware level
Short Notes

Primitive DS: Basic, machine-level structures

Types: Integer, Float, Character, Pointer

Key Features: Built into languages, direct hardware operation, fixed size

Representation may vary across computer architectures

Non-Primitive Data Structures

Detailed Notes
  • More sophisticated structures derived from primitive data structures
  • Emphasize structuring groups of data items (homogeneous or heterogeneous)
  • Major categories:
    • Linear Data Structures: Sequential arrangement
      • Arrays, Linked Lists, Stacks, Queues
    • Non-Linear Data Structures: Hierarchical/multi-connection

  • Common operations performed on non-primitive data structures:
    • Create, Selection, Updating, Searching, Sorting, Merging, Destroy/Delete
  • Design of efficient data structures must consider operations to be performed
  • Examples: Lists, Stack, Queue, Tree, Graph, Binary Search Tree, AVL Tree

Arrays

Detailed Notes
  • Definition: Set of finite number of homogeneous elements (same data type)
  • Declaration syntax: int arr[10]
    • int: Data type
    • arr: Array name
    • [10]: Size/length (10 elements)
  • Key characteristics:
    • Elements accessed by index: arr[0] to arr[9] (0-based indexing)
    • Elements stored in consecutive memory locations
    • Size calculation: (Upperbound - Lowerbound) + 1
    • Reading/writing requires loops (1 loop per dimension)
  • Common operations:
    • Creation, Traversal, Insertion, Deletion, Modification, Merging
  • Example code for array operations:
    int arr[10]; // Declaration
    // Reading array
    for(int i = 0; i <= 9; i++) {
      scanf("%d", &arr[i]);
    }
    // Writing array
    for(int i = 0; i <= 9; i++) {
      printf("%d ", arr[i]);
    }
Short Notes

Array: Homogeneous elements in contiguous memory

Declaration: type name[size] (e.g., int arr[10])

Indexing: 0-based (first element = arr[0])

Size Formula: (Upperbound - Lowerbound) + 1

Key Feature: Constant-time access by index

Operations: Traversal, Insertion, Deletion, Modification, Merging

Linked Lists

Detailed Notes
  • Definition: Collection of variable number of data items (nodes)
  • Each node contains at least two fields:
    • Data/Information field
    • Pointer/Address field (to next node)
  • Types of linked lists:
    • Single Linked List: Each node points to next node only
    • Doubly Linked List: Each node points to both next and previous nodes
    • Single Circular Linked List: Last node points back to first node
    • Doubly Circular Linked List: Circular with both forward and backward pointers
  • Structure visualization:
    • Head → [Data|Next] → [Data|Next] → [Data|Next] → NULL
    • Linear arrangement but non-contiguous memory allocation
  • Advantages over arrays: Dynamic size, efficient insertions/deletions
Short Notes

Linked List: Collection of nodes (data + pointer)

Node Structure: Data field + Pointer to next node

Types: Single, Doubly, Circular (single/double)

Key Features: Dynamic size, non-contiguous memory, efficient insert/delete

Traversal required for element access (no random access)

Stack

Detailed Notes
  • Ordered collection with special access restriction: LIFO (Last In First Out)
  • All insertions and deletions occur at one end called TOP
  • Analogous to stack of plates: New plates added to top, removed from top
  • Key operations:
    • PUSH: Insert element onto stack
    • POP: Remove element from stack
  • Implementation methods:
    • Using Arrays (Static implementation - fixed size)
    • Using Pointers/Linked Lists (Dynamic implementation - flexible size)
  • Characteristics:
    • Base remains fixed during operations
    • Top changes with PUSH and POP operations
    • Non-primitive linear data structure
  • Applications: Function calls, expression evaluation, undo mechanisms
Short Notes

Stack: LIFO (Last In First Out) structure

Operations: PUSH (insert) and POP (remove) at TOP only

Implementation: Arrays (static) or Linked Lists (dynamic)

Key Principle: Last element added is first removed

Applications: Function calls, expression evaluation, undo/redo

Queue

Detailed Notes
  • Ordered collection with special access restriction: FIFO (First In First Out)
  • Elements added at one end (REAR) and removed from the other (FRONT)
  • Analogous to people standing in line: New person joins at rear, served from front
  • Key operations:
    • Enqueue: Add element to rear
    • Dequeue: Remove element from front
  • Implementation methods:
    • Using Arrays (Static implementation)
    • Using Pointers/Linked Lists (Dynamic implementation)
  • Characteristics:
    • Linear non-primitive data structure
    • Maintains order of insertion
    • Two pointers track front and rear positions
  • Applications: CPU scheduling, print spooling, network buffers
Short Notes

Queue: FIFO (First In First Out) structure

Operations: Enqueue at REAR, Dequeue from FRONT

Implementation: Arrays (static) or Linked Lists (dynamic)

Key Principle: First element added is first removed

Applications: Scheduling, buffering, resource management

Trees

Detailed Notes
  • Definition: Finite set of nodes arranged in sorted sequence (non-linear)
  • Represents hierarchical relationships between elements
  • Key components:
    • Root: Special node at top of hierarchy
    • Subtrees: Remaining nodes partitioned into mutually exclusive subsets
    • Tree grows downward (opposite of natural trees)
  • Structure characteristics:
    • Each node has exactly one parent (except root)
    • Nodes can have zero or more children
    • Nodes with no children are leaves
    • Organizes data into branches representing relationships
  • Types of trees: Binary trees, Binary search trees, AVL trees, B-trees
  • Applications: File systems, organization charts, decision trees
Short Notes

Tree: Non-linear hierarchical structure

Components: Root (top), Nodes, Edges, Leaves (no children)

Key Property: Each node has exactly one parent (except root)

Tree Direction: Grows downward (root to leaves)

Applications: Hierarchical data representation, file systems

Graphs

Detailed Notes
  • Mathematical non-linear structure representing physical structures
  • Formal definition: Graph G(V,E) = Set of vertices V + Set of edges E
  • Components:
    • Vertices: Points/circles representing entities
    • Edges: Arcs/line segments connecting vertices
    • Edges may have weights (length, cost, etc.)
  • Graph types:
    • Directed: Edges have direction (digraph)
    • Undirected: Edges have no direction
    • Weighted: Edges have associated values
    • Simple: No loops or multiple edges
    • Connected: Path exists between any two vertices
    • Non-connected: Disconnected components
  • Applications: Networks (social, computer), maps, relationship modeling
Short Notes

Graph: G(V,E) = Vertices + Edges (non-linear)

Components: Vertices (nodes), Edges (connections)

Key Types: Directed/Undirected, Weighted/Unweighted, Connected/Disconnected

Edge Weights: Represent cost, distance, capacity, etc.

Applications: Networks, maps, relationship analysis
